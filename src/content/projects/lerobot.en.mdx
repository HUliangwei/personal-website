## Overview

This is an **Embodied AI learning map**, not a completed LeRobot or ACT implementation. The current public evidence supports only a Learning Project · In Progress framing, so the page communicates states and evidence gates without turning planned tools, training stages, or outcomes into experience claims.

## Problem / Motivation

The goal is to divide embodied AI into questions that can be verified step by step: how a task is defined, how data is formed, how a policy is trained, and how results are evaluated. No project artifact yet establishes a specific task, hardware platform, or simulation environment, so completed collection, training, inference, and deployment are not claimed.

## My Role

The present role is learner and roadmap builder: framing questions, defining evidence gates, and keeping “planning to learn” separate from “implemented.” Work without a repository, experiment record, or reproducible run is not counted as a personal result.

## Architecture

The learning map uses four states:

- **Learned:** the public evidence boundary is understood; no technical milestone is currently marked complete.
- **Practicing:** breaking a target task into verifiable questions about data, policy, run records, and evaluation.
- **Planned:** Linux, ROS2, Gazebo, MuJoCo, LeRobot, and ACT are not yet verified as technologies used in a project.
- **Next:** VLA, VLM, and VCT are not yet verified as studied or implemented topics.

## Design / Method

The method starts with evidence rather than a tool list. Each stage needs a defined task, traceable and licensed data, a reproducible environment, training logs, checkpoints, inference output, and an evaluation protocol before its state can move from Planned to practiced project work.

## Implementation

No audited implementation artifact currently supports a public technology stack. Linux, ROS2, Gazebo, MuJoCo, LeRobot, and ACT remain **Planned / not yet verified** and do not appear as completed technologies on the card or project metadata.

## Verification / Experiments

Evidence gates include traceable data, an environment lock, training and inference records, a defined evaluation task, and reproducible results. Those gates have not yet been met, so this page makes no completed-experiment claim.

## Results

The current result is an evidence-first learning map. No end-to-end completion or quantitative accuracy, success-rate, or performance result is claimed.

## Challenges & Decisions

The central decision is to resist treating tool names as project experience. Planned technologies can explain direction, but only reproducible artifacts can change their public state.

## What I Learned

The present learning outcome is a clearer study and verification framework. Technology-specific outcomes will be described only after project artifacts support them.
